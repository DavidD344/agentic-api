# ADR 0011: Semantic inferences to complete RF01 and support analysis

Status: accepted

## Motivating Requirement

RF01 requires sex, state, research area and doctorate completion year. The initial document suggested a `genderGuesser_agent` and also raised the question of whether we should add more information beyond what was required.

RF02 and RF04 also benefit from derived data: dashboard and chat become better with topics, areas, tags and summaries.

## Architectural Problem

Not every field appears as a clean table. Some fields must be extracted or inferred:

- state from institution;
- region from state;
- sex from name/text;
- main area from summary;
- topics and methods from curriculum;
- international experience, management and outputs from sections.

Sending the entire curriculum to the LLM would be expensive. Pure regex extraction would be fragile.

## Decision

We will create an `inference_agent` with two layers:

```txt
local rules
  for deterministic or near-deterministic fields

cheap configurable LLM
  for validation and semantic fields
```

Default model:

```txt
INFERENCES_LLM_MODEL=gpt-5-nano
INFERENCES_REPAIR_LLM_MODEL=gpt-5.4-mini
INFERENCES_LLM_MODE=split
```

## Rationale

Fields such as region should be calculated deterministically. Fields such as research area require semantic interpretation.

The split mode reduces timeouts and malformed JSON:

```txt
rule_validation
semantic_generation:research
semantic_generation:career
semantic_generation:experience_outputs
semantic_generation:dashboard_qa
```

## Resulting Behavior

Local-rule fields:

```txt

scholarship_category

```

Semantic fields generated by LLM:

```txt

research_topics

application_domains

academic_rank
seniority_level

```

Each inference stores:

```txt

confidence
source
reason
needs_review
```

## Handoffs

```txt
lattes_full_agent -- structured curriculum --> inference_agent
inference_agent -- profiles_with_inferences --> dashboard_agent/query_agent
```

## Guardrails

- `sex_inferred` is a statistical inference, not an official data point.
- Text sent to the LLM is limited by configuration.
- Evidence snippets are selected from the curriculum.
- Errors are repaired with a better model only when needed.
- Limited runs do not promote `current.json`.

## Consequences

Advantages:

- completes required fields;
- improves dashboard;
- improves chat;
- reduces cost with the nano model;
- records uncertainty by field.

Limitations:

- inferences may be wrong;
- prompt changes may change results;
- some information remains uncertain;
- clear documentation is needed to avoid confusing inference with official source.
